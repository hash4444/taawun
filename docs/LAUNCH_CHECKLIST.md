# Controlled UAE launch checklist

Updated 2026-10-15. Status: **local implementation; launch blocked on staging and operational approval**. Check only items verified in the target environment. Automated results are recorded separately in TEST_REPORT.

## Engineering

- [x] Initial full source/migration/function audit saved before major changes.
- [x] Development branch; production branch/database/deployment untouched.
- [x] Trusted roles, real verification hydration, guarded routes and standard OAuth callback code.
- [x] Student academic profile, explicit18+/eligibility declarations, resumable progress and four primary destinations.
- [x] UAE/AED jobs, discovery, transactional hiring stages and durable in-app notifications implemented.
- [x] Private preferred windows/manual busy periods/ICS import/disconnect and explainable schedule matching implemented.
- [x] Approval-first assistant; default-disabled paid calls, cron and automatic/external submissions.
- [x] Default-off isolation of financial/attendance/fixture-heavy legacy modules.
- [ ] Full clean-clone CI run on the final PR commit, including browser/Edge/migration tests.
- [ ] Real Supabase local/staging Auth/PostgREST/Storage integration rehearsal and advisors.
- [ ] Confirm each RLS/column/execute grant and negative access scenario on the deployed schema.
- [ ] Audit historical privileged roles and legacy verification evidence with a trusted operator.
- [ ] Verify production-like email confirmation, password recovery, sign-in provider callbacks and rate limits.
- [ ] Direct Google/Microsoft OAuth token encryption, state/PKCE, refresh/revocation and consent tested if enabled. ICS/manual are the currently supported calendar paths.
- [ ] Retention/account deletion/export and signed-file access tested operationally.
- [ ] Final mobile/desktop and Arabic keyboard/screen-reader/contrast review on supported browsers (Safari/Firefox are not established by Chromium tests).
- [ ] Staging hosting history/CSP/cache/deep-link checks and load/pagination tests.

## Business, privacy and operations

- [ ] Confirm exact cloud project and hosting target; obtain migration/deployment authorization.
- [ ] Professional confirmation of UAE operating licence/model, permit responsibility and employer terms.
- [ ] Approved student/employer privacy notice, lawful processing, consent/retention and cross-border handling.
- [ ] Verification staff, abuse reporting, incident response, support and data-request ownership.
- [ ] Backup/restore and secure rollback rehearsed; release owner and maintenance plan named.
- [ ] Paid infrastructure/provider budgets and alert limits explicitly approved before enabling any cost gate.
- [ ] No payroll/fees/contracts/regulatory placement service or school-age launch without its separate approved model.
- [ ] No unconfirmed university/corporate partnership claim; TAAWUN Experience deferred.
- [ ] Final controlled-launch business/legal/privacy/security approval recorded.

Passing local tests does not complete unchecked gates. Automatic applications and future modules may remain disabled.
